# Free World (0.15.16)

Enter through FREE WORLD at the north end of the hotel corridor (E). The shared grassland is 300 × 300 m with glacier cliffs, a protected entrance, a 24 m build ceiling and a half-metre construction grid (not drawn). A concealed sealed door is reserved for a future world.

| Control | Action |
|---|---|
| I | Shared inventory: weapons, building block and own 3D models |
| 1–3 / T | Select game weapon / reload |
| 4 / mouse wheel | Select reusable building block with configured size, shape and image; remains selected after new placement |
| E | Pick up own intact object or place held object |
| + / − | Model: 0.1 m increments (0.1–4 m); block: 0.5 m increments (0.5–4 m) |
| Q / F | Rotate held object by 90 degrees |
| B | Attach held model to aimed wall |
| G | Place held object |
| 0 | Holster weapon or cancel held preview |
| R / Delete | Repair / remove own aimed object |
| Left click | Place selected block or use selected game weapon |
| Right click | Remove aimed own block with reusable block selected; otherwise retain existing placement/zoom behavior |
| E at HOTEL door / phone | Return to corridor |

All accounts in the same server share the same persisted construction space. Blocks snap to a grid and have collision; supported surfaces and stacked blocks can be used as platforms. Players can remove their own blocks only. The server protects the spawn area, bounds placement, prevents overlapping blocks and enforces 240 blocks/account and 1,200 total. The phone app accepts local PNG/JPEG/WebP up to 8 MiB, re-encodes to a JPEG with longest dimension at most 512 px and at most 256 KiB, and applies it to all faces of newly placed blocks. Images are visible to everyone in Free World. 8 images/account, 64 globally, delete unused own images. Texture and block data are stored in free_world.sqlite3 in the existing data volume. No external URL fetch. The existing game weapon models are selectable directly from the inventory with shared server-controlled game damage, health, respawn and cooldown; the private-room damage system is not used. Existing blocks keep their coordinates; the entrance and spawn move to the new outer wall. All Free World participants are vulnerable except during short spawn protection. No cross-world targets. Presence and scores are session-based; construction persists. Desktop and touch are supported; immersive XR is not enabled in this initial version. Account and admin permissions remain unchanged.

## Shared models, sky and damage (0.14.3)
Select a private GLB in the Free World phone app, or import a new one there. Placement explicitly copies the asset into shared storage; the private original is never published automatically. Model size is independent of the block grid; the selected metric size defines a conservative cubic collider. Four model placements per account, 16 globally, 128 MiB of shared model bytes. Removing the final public copy removes its shared bytes but never the private original. Blocks and model placements have persistent HP, use hotel game damage classes, and can be repaired or removed by their owners. Destroyed placements reserve their grid footprint but do not collide; R repairs and Delete removes them when aimed at their footprint. Model impacts use authoritative grid displacement rather than independent Rapier rigid-body simulation. The roof is open, the build height remains 24 m, and the 20-minute synchronized sky cycle includes sunrise, sunset, sun and moon. HUD controls appear briefly on entry or object selection; the phone retains all controls.

## Unified inventory (0.14.4)
There is no build/PvP mode toggle. All controls remain available in the shared world; taking an object holsters the selected weapon, and weapon selection cancels the held preview. Choose or import a GLB, then select **Modell aufnehmen**. Existing intact owned objects can be picked up and edited with E. Changes are committed atomically when placed, preserving the object ID, asset, health and texture. The original shared placement remains until the new location is accepted; both old and new locations must be within reach. Model positions and 90-degree rotations are stored independently of the grid, with revision checks for concurrent edits. Blocks remain snapped to the half-metre grid and preserve selected image textures. Shared models still use conservative box collisions and server-controlled impact displacement, not the full private-room rigid-body simulation.

## Wheel inventory and flashlight (0.14.6)
Mouse wheel cycles empty hand, three weapons and the reusable block in both directions. Rotating or resizing the new block updates the current preset. Existing objects and held GLB models still require deliberate cancellation. The smartphone flashlight app toggles a local, 28 m directional spotlight in the room, hotel corridor and Free World; it remains on when the phone is closed and across transitions. Other clients do not see the beam. Immersive VR does not use the lamp.

## Mouse building (0.14.7)
Select the reusable block with 4 or the mouse wheel. Left click places blocks; right click removes an aimed own construction block. The preset stays selected after both operations. Imported models and other players' blocks are excluded from this right-click removal; ordinary object editing remains available. Server ownership, distance and version checks are unchanged. On touch devices, the build controls show Setzen and Entfernen.

## Hidden village (0.15.0)
A concealed village in the western half has four houses, a market, a cafe, streets and a dense forest. Trees are instanced and their health is shared and persisted; a destroyed tree leaves a decorative stump. Buildings are exterior-only solid obstacles. Four training NPCs patrol and defend themselves when hit; they respawn after 15 seconds. Their simple obstacle avoidance is not full navigation. Existing player builds are never replaced by scenery. The optional local building bank uses static self-contained GLBs; see [optional-village](../optional-village/README.md). Quaternius Downtown City MegaKit is the selected CC0 source, but its original archive is not bundled yet. The built-in facades are temporary procedural replacements.

## Prepared Quaternius models (0.15.1)
Install the separately supplied prepared `Second-Live-Quaternius-Village-Models.zip` through Smartphone → System → Dorfmodelle importieren. Only the activated administrator may import. The four GLBs are validated and atomically stored in `village_assets.sqlite3` in the existing data volume; no external requests or subsequent rebuilds are required. Reload the game to activate the new art. Imported entrances face the street and shop labels remain visible. Buildings are still solid exterior-only collision boxes, and all previous scene coordinates and tree damage stay unchanged. The original Standard archive is not directly accepted; use the prepared four-model ZIP. See [asset instructions](../optional-village/README.md).

## Living village (0.15.2)
Training NPCs transmit explicit walking state and velocity. The client smooths the positions and heading and adjusts the walk cycle to movement speed. Each building has 268 damageable shell cells, using the same four damage stages as the hotel but a simplified grid, not its exact Voronoi wall geometry or full rigid-body building collapse. The original installed GLB textures stay visible on intact fragments. Destroyed cells stop colliding and their temporary debris is visual. Aim at damaged or destroyed parts and press R; Shift+R rebuilds the whole building. Shared repairs are refused when a restored cell would overlap a player, NPC or existing construction. Interior geometry remains limited to what the installed GLB contains. Damage is persisted. Street surfaces, sidewalks, curbs, crossing, lights and tree geometry were redesigned without extra downloads. Fallen trees regain 100 HP after 24 real-world hours; their due time persists across restarts. Old stumps acquire a new deadline at the first database migration. A blocked trunk volume postpones regrowth until empty. World day/night length remains unchanged. All existing original village models stay installed.

## Voronoi fractures and NPC motion (0.15.3)
Village walls and slabs use the hotel's deterministic jittered Voronoi site/polygon algorithm. Six nonoverlapping shell surfaces retain the 268 legacy IDs per building. Existing damage remains assigned to the same IDs, although the old rectangular outlines become irregular. The original GLBs use nearest-site masking, and the hotel boundary function generates textured exposed fracture faces. Host and client use the same polygon-prism ray and overlap tests. This is game-surface destruction, not full structural collapse. NPC simulation advances in 50 ms steps; timestamped samples are interpolated behind the latest update by about 340 ms. Defeated NPCs fall over and stay visible for 10 seconds, are excluded from live targeting and collision, and respawn after 15 seconds if their home is clear. The fall is animated, not a ragdoll physics system.

## Compact building HUD (0.15.4)
While holding a block or model, the Free World interaction panel docks at the bottom center. Size buttons remain available and the map and transient notices avoid the dock. Touch mode keeps large size buttons and omits redundant keyboard instructions. Normal interactions and the hotel HUD are unchanged.

## Continuous NPC locomotion (0.15.5)
The village NPC flag is supplied before animation loading, so the same in-place clip preparation already used by hotel staff removes horizontal hip/root motion from all NPC locomotion clips. The server route is the only source of world translation. The client samples a monotonic, delayed timeline (420 ms target buffer) using confirmed positions only. Old and duplicate packets are ignored; after exhausting the confirmed path during a connection stall, the NPC waits for a new sample. The server pauses blocked patrols, and reverses only at the normal waypoint after a stationary 450 ms turn. Movement pace is derived from actual displayed displacement. Corpse timing and respawn are unchanged. A blocked path does not yet invoke full pathfinding.

## Natural NPC gait (0.15.6)
Village NPCs walk at 1.35 m/s and send up to 32 confirmed samples at the 20 Hz simulation rate, including heading and pace. The client interpolates a delayed trajectory with a 500 ms target buffer and gentle clock correction, derives stride playback from the whole movement segment, and keeps idle and walk clips alive with complementary weights. A brief stop does not restart the walk cycle. Frame-time handling supports rendering down to 4 FPS before the safety cap applies; tests exercise 8 to 144 FPS. The turn pause is 650 ms; hotel NPCs and death/respawn behavior are unchanged. The original GLB appearance still requires a visual game check.

## Sidewalk patrols and streetlights (0.15.7)
Two NPCs patrol on each of the two longitudinal sidewalks. Their default routes and spawn fallback positions stay on the sidewalk at 0.075 m above terrain. Pursuit may leave the sidewalk; after combat the NPC returns to its normal route. Eight staggered warm point lights (17 m range) illuminate the village locally. The sky's night factor smoothly controls illumination and emissive intensity. All streetlights turn off in daylight, and they use no additional shadow maps. The world sky, movement interpolation, NPC animations and persistent builds are unchanged.

## NPC cold-start fix (0.15.8)
Before the entry snapshot, the server ticks the village, including after extended idle periods. Each NPC snapshot includes `serverTime` from the same monotonic clock as `motionTime`. The client detects discontinuous motion timestamps or missing history, reanchors the playback timeline, and starts a newly created avatar at the delayed trajectory pose. Stale and duplicate samples remain ignored. Cold-start and respawn tests cover idle intervals from zero to one hour. Existing gait blending, sidewalk routes, death timing and streetlights are unchanged.

## NPC hit reactions and surface marks (0.15.9)
Regional NPC hit volumes are simplified arcade collision triggers. Head hits trigger immediate defeat and a faster fall; surviving torso/leg hits trigger a short stagger, and injured legs affect movement pace and the reversible pose overlay until respawn. No change to healthy movement, player damage rules, or death/respawn durations. The fictional rifle ray and its tracer extend to 300 world units/metres, bounded by game terrain and collision geometry; building/repair range stays 8 m. The hotel decal projection and material textures are reused for server-confirmed surface hits. A bounded SQLite table stores up to 384 shared marks (12 per target), cleared on repair, destruction or relocation. Inset imported geometry is projected only where a suitable surface exists, and village fracture shaders clip building decals. Marks on a model moved by a hit are not retained. Rendering with installed GLBs needs an in-game check.

## Clean impact surfaces (0.15.10)
The village fracture shader now only discards destroyed cells, including in shadow and decal materials. Surviving surfaces retain the original GLB textures and no longer show procedural crack overlays or whole-cell darkening. Existing localized impact decals, exposed fracture geometry, collision, persistence and repair are unchanged.

## Open village (0.15.11)
Each existing building has a centered street-facing entrance and a separately animated door leaf. The server and client remove the matching aperture from front-wall Voronoi prisms, retaining the 268 original fracture IDs and adding door ID 448. A closed intact door blocks the entrance; an open leaf uses simplified collision. Press E (or the touch interaction button) near the entrance to open or close it. Doors auto-close after about seven seconds unless occupied. Destruction and repair persist; intact doors start closed after a server restart. Prepared Quaternius GLBs have their original door triangles isolated at runtime, with a procedural fallback for other assets. The ground floor is accessible, but not furnished or connected to upper levels. Four male and two female Rocketbox NPCs use staggered scripted indoor visits between sidewalk patrols; no full indoor pathfinding. NPC name tags are removed, player labels are unchanged.

## Bundled village assets (0.15.12)
The Docker build supports the prepared CC0 ZIP at `optional-village/Second-Live-Quaternius-Village-Models.zip`. When present in the Git checkout, the build checks the original SHA256, validates all four static GLBs, copies the license/report and writes the local asset manifest. No browser-side download or admin import is required. Existing database imports take precedence. Without the ZIP the build still supports standalone GLBs and procedural fallbacks. See `optional-village/README.md` for the exact package path and checksum.

## Living interiors (0.15.13)
The six ground floors have a server-defined layout with 80 furniture items, stable IDs starting at 512 per building and the existing four damage stages. Houses contain living, sleeping, kitchen and dining furniture; the market has stocked shelving and a register; the café has tables, chairs and a coffee counter. Procedural textured meshes are batched per material, without new asset downloads. Furniture has approximate AABB collision, damage and repair, and local impact projection where a matching mesh exists. Conflicting existing builds suppress their default furniture; repair restores it once clear. Up to four nearby warm indoor lights become brighter at night. Visitors pause for 8–12 seconds and face a nearby fixture with a reversible idle pose overlay; the existing movement and combat logic remain intact. No furnishing of upper floors, actual sitting, service transactions, or new characters in this release.

## Shared seating (0.15.14)
Aim at a furnished chair within 2.5 m and use E (or the touch interaction) to sit. The server owns the seat ID, floor anchor, facing direction, and occupancy. Look around freely, switch camera using V, and press E again to stand. Movement, equipment and building edits are disabled while seated. The server validates the approach and selects an unobstructed exit position; a blocked exit leaves the player seated. Destroyed seats or missing support release occupants; if no nearby safe exit exists the normal spawn is used. Disconnect and respawn release occupancy. Seated player poses are synchronized, using the existing hotel rig overlay; hotel seating and NPC routines remain unchanged. Only the provided village chairs are supported, not arbitrary imported models.

## Dynamic weather (0.15.15)
Snapshots include the server wall-clock `weatherTime`, aligned with `dayPhase`. All clients derive an eight-minute continuous repeating clear/cloudy/rain/thunder/clearing cycle and five deterministic distant lightning events per storm. Shader clouds drift; rain uses at most 1,400 reusable local streaks, clipped by spatially indexed existing solid collision geometry (half-metre shelter samples, exact query for indoor audio). Fog, daylight and lamps respond to weather. Thunder is delayed and rain audio is filtered/attenuated under cover; both use synthesized local audio and existing sound settings. No new downloads, damage, precipitation persistence, or extra shadow maps. Weather is visible in the Free World HUD; other areas remain unchanged.
